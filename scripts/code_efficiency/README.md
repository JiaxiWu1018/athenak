# Benchmark implementation

The source branch is experiment/code-efficiency from origin/NRPIC ca0f5298. The dedicated problem generator is particles/code_efficiency. ST profile construction is selectively imported from b51efb27; the complete freeze is selectively ported from320ba2b0. Production pusher, interpolation, deposition and migration algorithms are preserved.

Inputs use a newly registered <benchmark> block. Controls: enabled (master instrumentation switch), profile (synchronized phase timers), mesh_only (hold initialized source and skip particle advancement), metric (st/flat), sampling (random/replicas), distribution (uniform/central4/central1/block/point), n, ppc, seed, yc and warmup. All instrumentation defaults off. z4c/frozen_background separately defaults false. Four ghost zones, fresh uniform3D mesh and particles+Z4c are required for this pgen.

Random draws use a deterministic global-ID counter hash. Replica sampling assigns the same normalized ST rest-mass budget and monoenergetic six-direction velocity distribution to every occupied cell. Replicas share positions and velocities and divide mass by multiplicity. Vacuum cells retain zero-mass, initially stationary particles. Counts and tags remain independent of rank assignment. Integer allocation for concentration uses deterministic largest-remainder rounding, equally for each of six directions.

Timing covers completed evolution after0.5M with GPU fences at its start/end and a maximum over ranks. nlim is the exact target cycle count to prevent an extra near-zero step at the endpoint. Main throughput uses the release executable without per-phase fences or device-clock instrumentation. Phase profiles use the release executable with profile=true. Device-clock estimates use the separately compiled pusher; they never supply the phase-cost ranking.

Audits check count and modular tag checksums, payload hashes, finite particle/geometry data, ownership, no destruction, fixed background hashes including ghosts and both pusher time levels, and initial source against the common six-direction cell reference. Numerical comparison additionally tests frozen release versus instrumented payloads. Failed attempts are retained; a retry creates a new attempt directory and preserves the previous receipt.

The validated Perseus MPI launch uses --bind-to none and one GPU per rank. Core binding failed under the Slurm allocation before any simulation. The scheduler enforces at most two CPUs per GPU. Toolchain: OpenMPI5.0.7 at /home/emost/codes/openmpi, CUDA12.9, Kokkos AMPERE80, MPI, double precision, Release. Runs write no scientific snapshots or restarts.

Set EFFICIENCY_SESSION to relocate the launch package to another dated Perseus session. Keep its scripts/, jobs/, inputs/, matrix.json and gates.json layout and an independent source clone at src/athenak. Build directories are temporary; binaries/release/athena and binaries/profile/athena are stable run artifacts. Exact source, build environments, command lines and executable hashes are retained under provenance/ and each result receipt.

Scheduler continuation: scripts/advance.py preserves interrupted attempts, resubmits preempted four-rank gates and updates their dependent jobs. jobs/close.sbatch checks coverage, retries unsuccessful cases twice in new attempt directories, regenerates reports and writes CLOSURE.md. The live job ledger is provenance/jobs.jsonl; recovery state is provenance/recovery.json.

Release/profile isolation is now verified in every timing receipt through device_timing_compiled, emitted by the actual pusher translation unit. jobs/verify_build.sbatch forces both OFF/ON pusher compiles and compares frozen particle payloads; release device cycles must be zero, instrumented cycles nonzero, and a short Nsight timeline must exist. Early compile-mode-contaminated timings remain explicitly superseded in preserved attempt directories. NVTX capture uses NSYS_NVTX_PROFILER_REGISTER_ONLY=0 for the unregistered range string, as documented in the [NVIDIA Nsight Systems guide](https://docs.nvidia.com/nsight-systems/UserGuide/index.html).

The small frozen numerical gate retains native-slot payload tables for10,000 particles, aligns them by tag, requires exact masses/tags and a maximum scaled state difference below1e-12, and records bitwise hash agreement separately. These audit tables are outside all timing windows. Each case also retains a checksum manifest of its outputs.

Instrumented particle selection uses a32-bit tag hash and a1/1024 probability, avoiding aliases with structured cell/velocity order. The numerical gate compares the actual GPU sampled-step count with an independent host calculation; provenance/sampling_audit.json records direction/column coverage of a6.29M-particle uniform realization. The release executable remains immutable across this diagnostic correction.

Remaining one-rank/four-rank groups may use separate dependency chains to backfill resource waits. Each group is serial; four-rank jobs consume all four enforced per-user debug GPU licenses, so the two groups cannot overlap. Closure depends on both tails. Exact scheduler/license proof is in `provenance/license_serialized_chains.json`; the watcher flags any unexpected overlap.

User-approved largest-case revision: the five throughput cases with N >= 100 million end at 1M after a 0.5M warm-up (ten measured cycles). Smaller cases end at 5M; phase/device diagnostics end at 1.5M. Exact endpoints and duration limits remain explicit in the report and receipts.

Active monitoring may invoke `scripts/retry_preempted_tail.py` after a scheduler preemption. It retries only the latest PREEMPTED measurement without a valid receipt, appends to the correct serial group, verifies the four-license pool and joins both tails before closure. Numerical failures require diagnosis. A failed queue transaction leaves closure held with its exact commands recorded for repair.

The persistent watcher reloads monitor.py every50 seconds. A newly recorded scheduler interruption invokes the queue-tail recovery helper before writing the heartbeat, so retry submission and closure dependencies continue without an interactive agent turn. The helper lock prevents duplicate recovery; numerical failures still stop for inspection.
